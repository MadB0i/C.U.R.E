                                          INCIDENT STATUS

                                          —
                                          What do DIRECT / STRONG / PARTIAL / WEAK / NONE mean?
                                          • DIRECT — finding's executable path matches the observed executable path (normalized). Service entries additionally require the reported PID to match. Matched path + process.
                                          • STRONG — finding command and observed command line reference each other (executable substring either direction, or shared distinctive arguments ≥12 chars) with the launch inside the window. Matched command/path + timing.
                                          • PARTIAL — same executable file name, different paths (both shown). Matched name only.
                                          • WEAK — same folder but different program, or a child of a correlated process. Temporal/structural proximity only.
                                          • NONE — no observed relationship.

                                          Correlation does not by itself establish malicious intent. Levels and verdicts are deterministic — see the methodology note in the report export.

                                          OBSERVATION WINDOW / SCOPE

                                            Command lines are fetched only for correlated processes (bounded). Window evidence is titles + classes only — no screenshots, no keystrokes, no contents.

Unavailable values say “Not collected”. Long values truncate visually — hover or focus to see the full value; all evidence text is selectable.

                                                      Observation could not run or produced no usable data. This is not a clean bill of health.

                                                      LIMITATIONS — WHAT COULD NOT BE OBSERVED

                                                      • Sub-500 ms processes may be missed (snapshot + WMI delivery timing).
                                                      • Command lines are collected only for correlated PIDs.
                                                      • PIDs are re-validated before any action; PID reuse is handled, not assumed.
                                                      • No persistence or reboot capture — observation installs nothing.
                                                      • Window/process lifetimes carry ±500 ms poll precision where applicable.
